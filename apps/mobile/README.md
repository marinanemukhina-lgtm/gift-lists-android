# Android — locally bundled gift lists

Package proposal: `ru.nemukhina.giftlists`, label «Список подарков». This is a separate application, not the legacy Site and not the tax app. No package uniqueness or store approval is claimed.

## Build

From repo root install locked dependencies, supply JDK21, Android SDK36, build-tools35.0.0 (AGP8.13.0 default), then run `bash scripts/mobile-build.sh`. The script checks JDK21 (including javac) and installed platform36/build-tools35.0.0 before building, then uses the checked-in Gradle8.14.3 wrapper with its pinned distribution checksum. It builds real Vite assets, syncs Capacitor8.5.3 and compiles/lints **unsigned release only**. Native minSdk26 / target36. Debug and release signing configurations are deliberately absent; no keystore is created or reused. Root owner must separately authorize final signing and runtime QA.

Build-time public, non-secret configuration:

- `VITE_API_ORIGIN=https://<authorized-demo-host>`
- `VITE_PUBLIC_ORIGIN=https://<authorized-public-host>`
- `VITE_SUPPORT_CONTACT` (operator-approved, optional until release)

Origins must be HTTPS origins without paths/query/credentials. Unconfigured origin keeps local editing available and makes network publishing/share fail explicitly. Changing hosts requires rebuilding; Vercel URLs are not promised portable. This build always labels temporary synthetic-only demo usage; it is not a commercial production authorization.

## Boundaries

- `dist/index.html` and shared UI are bundled. No `server.url`, remote executable UI, `allowNavigation`, mixed content or cleartext API transport.
- Official App, Network, Browser, Share and Filesystem plugins. Native Share permits only configured `/e/<random-code>` guest links; no recovery/owner credentials or files. Merchant HTTP(S) URLs open a browser outside the privileged WebView.
- Secrets use pinned `@aparajita/capacitor-secure-storage@8.0.1` native Android implementation (Android Keystore/AES-GCM). A native capability call verifies the actual registered SecureStorage PluginHandle; Android/native/plugin checks then occur before every credential operation. Its insecure web fallback is never accepted. Credentials, pending recovery rotation and guest secrets are separate from ordinary cached drafts.
- Private Filesystem values are serialized/bounded and replaced through a pending/backup file; shared draft adapter adds verified two-slot revisions. No broad storage permission. Both pre31 and 31+ backup/device-transfer rules exclude data; `allowBackup=false` as well.
- `GiftDocumentsPlugin` uses Android's system `ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT`. One chooser at a time, explicit cancellation, off-main-thread provider I/O, max1MiB UTF-8, no persistent URI permission, no generic file sharing. Recovery file content is sensitive and should be saved privately.
- Native system-bar/IME insets keep editor above keyboard; Android Back first dismisses focused input, then delegates UI state, then minimizes at root. Resume invalidates guest availability in shared UI before network refresh.
- Minimum supported WebView100 is explicit. A bundled startup message explains upgrade needs rather than leaving a blank screen. Network callbacks are only hints, not proof of booking success.

## Tests and remaining acceptance

`node --import tsx --test apps/mobile/tests/*.test.ts` exercises fail-closed credentials, scope separation, pending recovery round trip, interrupted file replacement/restart, serialized revisions/bounds and guest-only sharing policy. Native `:app:testReleaseUnitTest` additionally exercises real SAF payload decoding/size/name validation without Android UI. These are deterministic adapter tests, **not Android runtime proof**.

Required root-owned real-device/emulator acceptance: fresh launch airplane mode; process-death draft persistence; system picker cancel/success/malformed UTF-8/oversize; genuine native encrypted persistence and recovery after uninstall; guest share/browser return; Back/keyboard/safe areas; TalkBack/large text/narrow screen; API26 and target36/no-Google-service paths; installation/upgrade/signature checks. No runtime device result is inferred from compilation.

Native template provenance: generated by installed official Capacitor CLI8.5.3, not copied from another product. Vector gift icon is code-native artwork using the reviewed product palette; no third-party image/font service. Final store icon approval remains a release gate.

The locally prepared [manual CI acceptance workflow](CI-ACCEPTANCE.md) targets the release variant with ephemeral test signing only after root review/dispatch. It has not been run by this worker. Exact unsigned artifact verification is retained in the local release handoff, not in published source. Local compilation and a test-signed APK are not RuStore readiness.
